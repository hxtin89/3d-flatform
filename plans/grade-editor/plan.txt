1. PIPELINE PLACEMENT

1.1 Where the tap sits
- One trilinear 3D-texture tap, display-referred.
- It sits after three's renderOutput (tone fn, then the sRGB OETF; RenderOutputNode.js:108-141) and before the canvas write, in the single full-screen quad of the RenderPipeline.
- The input is the encoded frame in [0,1] that a screenshot shows.
- Alpha is 1 everywhere, so un/premultiply are no-ops.
- The grade works with every tone curve and with the tone stage off.

1.2 The two paths
- Path A (DoF and/or EDL on, the shipping default): no new pass. The existing final quad gains the tap.
- Path B (DoF and EDL off): while the grade is compiled in, the frame goes through the same RenderPipeline with effectNode = scenePass.getTextureNode(). That is scene → PassNode HalfFloat RT → one quad, the same pass count as renderer.render.
- While the grade is compiled out, path B is renderer.render exactly as today, so the ?dof=0&edl=0 fps baseline is unchanged.
- Gate M2 (section 7): if the routing delta (passthrough stage vs renderer.render) is over 0.02 ms, path B switches to the film-slot fallback (section 1.7).

1.4 grade-output.ts (new; three/TSL; node-importable, no DOM; imports grade-bake.ts with the .ts extension)

    import * as THREE from 'three'
    import { clamp, screenUV, select, texture3D, uniform, vec4 } from 'three/tsl'
    import { identityTexels } from './grade-bake.ts'

    export function makeLutTexture(n: number, texels: Uint16Array): THREE.Data3DTexture {
      const t = new THREE.Data3DTexture(texels, n, n, n)         // 4·n³ half bits, R fastest (= .cube order)
      t.format = THREE.RGBAFormat; t.type = THREE.HalfFloatType   // rgba16float / RGBA16F: filterable on WebGPU core and WebGL2
      t.minFilter = THREE.LinearFilter; t.magFilter = THREE.LinearFilter   // default Nearest would compile to textureLoad
      t.wrapS = t.wrapT = t.wrapR = THREE.ClampToEdgeWrapping
      t.generateMipmaps = false; t.unpackAlignment = 1; t.colorSpace = THREE.NoColorSpace
      t.name = 'grade-lut'; t.needsUpdate = true
      return t
    }

    export interface GradeOutput {
      readonly stage: (display: any) => any      // stable reference, so setOutputStage's identity check works
      readonly size: number
      /** Same n: swaps the data into the same GPU texture and returns the array it replaced (for the pool).
       *  New n: a new texture, the node value swapped, the old one disposed two frames later; returns null. */
      upload(texels: Uint16Array, n: number): Uint16Array | null
      setSplit(x: number): void                  // canvas x in [0,1]; left of it shows "before". 0 = all graded, 2 = all before
      split(): number
      update(): void                             // once per frame, before render: deferred disposal
      dispose(): void
    }

    export function createGradeOutput(n0: number): GradeOutput {
      let n = n0
      let lut = makeLutTexture(n, identityTexels(n).slice())     // a copy: the cached identity is never handed to three or transferred
      const lutNode = texture3D(lut, null, 0)                   // level 0 → textureSampleLevel / textureLod (precedent environment-layer.ts:366)
      const lutScale = uniform((n - 1) / n)
      const lutOffset = uniform(0.5 / n)                        // (rgb·(N−1)+0.5)/N: texel centres for lattice points i/(N−1)
      const compareSplit = uniform(0)
      const retired: { tex: THREE.Data3DTexture; frames: number }[] = []
      const stage = (display: any) => {
        const before = display.rgb.toVar()
        const uvw = clamp(before, 0, 1).mul(lutScale).add(lutOffset)
        const after = lutNode.sample(uvw).rgb                   // the clone keeps levelNode; no derivatives, Firefox-uniformity safe
        // uniformFlow: a real select/ternary, both operands inline, never a branch (ConditionalNode.js:146-158)
        return vec4(select(screenUV.x.lessThan(compareSplit), before, after).uniformFlow(), display.a)
      }
      // Built differently (C2): as written above the frame is generated twice, because
      // ConditionalNode isolates each operand in its own node cache (ConditionalNode.js:104-105)
      // and display.a is read outside the select; building the frame inside the uniformFlow
      // context also turned EDL's selects into eager ternaries. grade-output.ts wraps the stage
      // in Fn(() => { const shown = display.toVar(); const after = lutNode.sample(...).rgb.toVar();
      // return vec4(select(...).uniformFlow(), shown.a) })(), and a shader test checks the frame
      // texture is read once.
      return {
        stage,
        get size() { return n },
        upload(texels, size) {
          if (size === n) {
            const prev = lut.image.data as Uint16Array
            lut.image.data = texels; lut.needsUpdate = true     // re-upload into the same GPU texture (Textures.js:346-355)
            return prev
          }
          retired.push({ tex: lut, frames: 2 })
          n = size; lut = makeLutTexture(n, texels)
          lutNode.value = lut                                   // sample() clones read .value via referenceNode; NodeSampledTexture rebinds
          lutScale.value = (n - 1) / n; lutOffset.value = 0.5 / n
          return null
        },
        setSplit(x) { compareSplit.value = x },
        split() { return compareSplit.value },
        update() {
          for (let i = retired.length - 1; i >= 0; i--) {
            if (--retired[i].frames <= 0) { retired[i].tex.dispose(); retired.splice(i, 1) }
          }
        },
        dispose() { lut.dispose(); for (const r of retired) r.tex.dispose(); retired.length = 0 },
      }
    }

2. GRADE MODEL (display-referred; all maths pure, in grade-model.ts / grade-curves.ts / grade-bake.ts)

2.1 Conventions
- x is the display-encoded sRGB value of a lattice node, in [0,1].
- Y' = 0.2126 R + 0.7152 G + 0.0722 B on the values at hand (Rec.709, the same weights as the film and point grades).
- srgbEotf and srgbOetf are the exact piecewise transfer (0.04045 / 12.92 / 2.4), odd-extended: f(−x) = −f(x).
- Wheel delta, the inverse Rec.709 Y'CbCr with Y' = 0, normalised so blue at u = 1 is 1:

    Δ̂(u,v) = (1.5748 v, −0.18732 u − 0.46812 v, 1.8556 u) / 1.8556

  - luma(Δ̂) = 0 exactly. Built: the green coefficients are derived from the luma weights
    (−Kb/Kg, −Kr·1.5748/(Kg·1.8556)); the rounded figures above leave luma at about 1.6e-6.
  - u = puck x (towards Cb, blue to the right); v = −puck y on screen (towards Cr, red up).
  - Red sits at about 103°, green at 230°, blue at 355° (this formula; 241°/347° are the NTSC
    Y'UV vectorscope figures).
- snapPuck: |puck| < 0.02 → exactly (0,0). It is applied on every set, and a double-tap resets.
- Tuning constants live in config grade.tuning and are referenced as k* below.

2.2 powC1(t, g), the C1 power, E = 1/64, valid for g in (0, 2]

    t ≥ E      : t^g
    0 ≤ t < E  : E^g · ((2−g)·(t/E) + (g−1)·(t/E)²)     (quadratic toe through 0, C1 at E)
    t < 0      : E^g · (2−g) · (t/E)                     (linear, C1 at 0)

- f(0) = 0, f(1) = 1, monotone and C1.
- Bit-exact identity at g = 1, because E is a power of two.
- This replaces `y > 0 ? y^(1/γ) : y`, which had a kink at 0 (judge 1, blocker 2).

2.3 GradeState v1: fields, ranges, defaults, steps

    temperature   −100..100      0      step 1     (+ warmer, Lightroom sign)
    tint          −100..100      0      step 1     (+ magenta)
    lift   {y,u,v}  y −0.25..0.25  0   step 0.001; puck in the unit disc, 0
    gamma  {y,u,v}  y −1..1        0   step 0.01  (log2 of gamma; + brightens mids)
    gain   {y,u,v}  y 0.5..2       1   step 0.01
    offset {y,u,v}  y −0.25..0.25  0   step 0.001
    contrast      0.5..2         1      step 0.01
    pivot         0.2..0.7       0.4614 step 0.001 (= OETF(0.18); shown as sRGB code, 118 = 18 % grey)
    saturation    0..2           1      step 0.01
    vibrance      −1..1          0      step 0.01
    curves {master, red, green, blue}   each 2..12 points [x,y], default [[0,0],[1,1]];
                  ends pinned at x = 0 and 1 (y free 0..1), interior x strictly increasing, gap ≥ 0.01
    hueSat        0..12 points [hue° 0..360, 0..2],  default []  (flat = neutral 1)
    hueLuma       0..12 points [hue°, −1..1 stops],   default []  (flat = neutral 0)
    tones { shadows {u,v} 0, highlights {u,v} 0, balance −1..1 0, blending 0..1 0.5 }
    rollOff       0..1           0      step 0.01
    version       1

The look is held beside the state, not inside it: `{ key, name, file | null, size, amount 0..1 (default 1) } | null`. The undo history stores the state and the look ref together.

2.4 Bake order per lattice node (i, j, k) → x = (i, j, k)/(n−1)

Stage 0: Look (optional)
- v = x + amount·(C(x) − x).
- C is the trilinear sample of the imported cube over its domain: u = clamp((x − dmin)/(dmax − dmin), 0, 1).
- Without a look, v = x.

Stage 1: per channel, on y = v_c. Every step is skipped at its neutral value.
- Without a look, these are exact tables at the n node values (3·n evaluations).
- With a look, they are dense tables of 4096 entries over [−0.25, 1.5] with linear interpolation. Built: cells where
  stage 1 bends hard (second difference / 8 above 1e-6, plus one cell each side) are evaluated exactly, which keeps the
  error under 0.001 LSB; plain linear tables measured up to 1.46 LSB on a step curve.

1a. White balance
- t = temperature/100 and τ = tint/100.
- Exponents in stops: e = (kTemp·t + kTint·τ/3, −2·kTint·τ/3, −kTemp·t + kTint·τ/3), with kTemp 0.5 and kTint 0.4.
- Gains: w_c = 2^e_c / (0.2126·2^e_r + 0.7152·2^e_g + 0.0722·2^e_b), so grey keeps its luminance.
- y = srgbOetf(w_c · srgbEotf(y)).

1b. Lift, gamma, gain, offset (Nuke Grade, equal to ASC CDL)
- Per channel:
  - L_c = lift.y + kLift·Δ̂_c(lift), kLift 0.10
  - G_c = gain.y · (1 + kGain·Δ̂_c(gain)), kGain 0.25
  - g_c = clamp(gamma.y + kGamma·Δ̂_c(gamma), −1, 1), kGamma 0.5
  - O_c = offset.y + kOffset·Δ̂_c(offset), kOffset 0.10
- Formula:

    y = y·(G_c − L_c) + L_c + O_c
    y = powC1(y, 2^(−g_c))                          (exponent clamped to [0.5, 2] by the g_c clamp)

- Lift moves black with white fixed, gain moves white with black fixed, gamma bends the mids.
- For later CDL export: slope = G − L, offset = L + O, power = 2^(−g).

1c. Contrast c about pivot p

    c ≥ 1 : y ≤ p → p·powC1(y/p, c);   y > p → 1 − (1−p)·powC1((1−y)/(1−p), c)
    c < 1 : y = p + c·(y − p)            (linear fade; no infinite end slopes; black rises to p(1−c))

- 0, p and 1 stay fixed for c ≥ 1, with slope c at the pivot.
- Above 1 and below 0 the curve extends C1.
- c = 1 is skipped.

1d. Curves: y = curve_ch(curve_master(y))
- Spline: Fritsch–Carlson monotone cubic Hermite.
  - Secants d_k.
  - Tangents: m_0 = d_0, m_last = d_last; interior m_k = (d_{k−1}+d_k)/2 if d_{k−1}·d_k > 0, else 0.
  - If d_k = 0, then m_k = m_{k+1} = 0.
  - If α² + β² > 9, scale both by 3/√(α²+β²).
  - Basis: h00 = 2t³−3t²+1, h10 = t³−2t²+t, h01 = −2t³+3t², h11 = t³−t².
- Linear extension beyond the ends with the end tangent.
- The default two-point curve returns null (skipped).

Stage 2: cross-channel, on y = (r, g, b), with the stage input v as the gamut reference. Computed once from the stage-2 input y:
- M = max, m = min, C = M − m, Y'.
- Hexcone hue H in degrees (undefined when C = 0).
- Hue gate q = smoothstep(0, kHueGate, C), kHueGate 0.05: greys and haze never move.
- Vibrance weight w_v = 1/(1 + Cq²/kVib²), kVib 0.3, where
  Cq² = ((r−g)² + (g−b)² + (b−r)²) / (2·(max(Y',0) + 0.02)²).
  This is smooth, uses no max/min, and gives saturated canopy about 0.1 and grey 1.

2a. Saturation, vibrance and hue-vs-sat in one affine step

    s = max(saturation · (1 + vibrance·w_v), 0) · (1 + q·(f_s(H) − 1))
    y ← Y' + s·(y − Y')

  For fixed s this is affine, so trilinear is exact until something clips.

2b. Hue vs luma
- y ← y + Y'·(2^(q·f_l(H)) − 1).
- This shifts all channels equally, so chroma differences are kept.
- f_s and f_l are periodic Fritsch–Carlson curves: points copied one period each side, tabulated to 361 entries (t[0] = t[360]), linear between entries.
- 0 points means skipped. One point is a constant.

2c. Split toning ("Tones")
- Y'' = luma after 2b; mc = 0.5 + 0.25·balance; bw = 0.2 + 0.6·blending.
- S = smoothstep(mc − bw/2, mc + bw/2, Y''), B = smoothstep(0, 0.06, Y''); w_h = S·B, w_s = (1 − S)·B.
  (Built this way: the earlier w_h = S tinted true black whenever the hand-over's lower edge reached below 0.06.)
- y ← y + kTone·(w_s·Δ̂(shadows) + w_h·Δ̂(highlights)), kTone 0.10.
- It is additive and zero-luma. True black stays black; the film's lifted black (about 0.1) is tinted.

2d. Input-relative soft gamut compression (no control; inactive unless the grade adds chroma)
- a = max(y), a_v = max(v). Skipped if a ≤ 1e-6 or a_v ≤ 1e-6.
- Per channel:
  - d = (a − y_c)/a, d_v = (a_v − v_c)/a_v, t = max(kGamut, d_v), kGamut 0.8.
  - If d > t and t < 1: y_c = a·(1 − (t + (1−t)·tanh((d − t)/(1 − t)))).
- C1 at the threshold, and colours the input already saturates are left alone. Not "never below 0": a
  channel that is exactly 0 at the input (a lattice face) is left alone and may go negative. Measured
  through the tap, that negative face value is what keeps dark canopy greens accurate (0.25 LSB max at
  saturation 1.1, against 1.1 LSB and 7 % of values over 1 LSB with the face held at 0). The canvas
  clamps per pixel; a .cube export carries the negative values, which stage 4 allows.

Stage 3: highlight roll-off, a second pass over the stored floats
- k = 1 − kRollKnee·rollOff, kRollKnee 0.3.
- W = max(1, peak), where peak = max over nodes of max(y).
- Skipped when rollOff = 0 or W ≤ 1.
- For a node with m = max(y) > k:
  - t = min((m−k)/(W−k), 1), n = (W−k)/(1−k);
  - m' = k + (1−k)·(1 − (1−t)^n);
  - y ← y·m'/m.
- This is the film shoulder's form: hue kept, C1 at the knee.
- It runs before the draft fill (section 2.6).

Stage 4: storage
- Finite check, clamp to [−16, 16], then round-to-nearest-even half.
- The fast path is Float16Array; otherwise a u32-view packer that is bit-identical.
- Alpha is 0x3c00.
- Values are NOT clamped to [0,1]. The 8-bit unorm canvas clamps per pixel after interpolation, so imported >1 values and hard clips interpolate as authored.
- three's truncating DataUtils.toHalfFloat is not used.

2.5 Identity: isGradeIdentity(state, look) is true when all of these hold
- Every scalar === its neutral value.
- All pucks are exactly 0.
- All four curves are the default two points.
- Each hue curve is empty or all its points sit exactly at neutral y.
- The look is null, or amount === 0, or isIdentityLattice(cube, 1e-5).
- rollOff is ignored, because a neutral grade has no value above 1. So are pivot (contrast 1 is skipped) and Tones
  balance and blending (both pucks at 0 add exactly 0): moving those alone bakes the identity lattice bit for bit, and
  must not compile an identity LUT in.
- A look counts as identity only if its domain covers [0,1] on every channel: a narrow-domain identity cube clamps.

A neutral bake equals identityTexels(n) bit for bit; every i/(n−1) is exact in half for n = 17, 33, 65.

2.6 Lattice size and draft
- Own lattice: config grade.lutSize, 33.
- With a 3D look of size N whose domain is [0,1]: L = latticeSizeFor(N) = the smallest k(N−1)+1 ≥ 33, capped at config grade.maxLattice (65).
  - 33 → 33, 17 → 33, 9 → 33, 21 → 41, 16 → 46, 32 → 63, 64 → 64, 65 → 65.
  - Trilinear on a refined lattice reproduces the cube's own trilinear exactly, also with amount < 1 and with controls on top. Measured within 0.10 LSB, which is half rounding only.
  - So moving a control on a loaded look causes no jump. Resampling to 33 would move outputs by up to 15-26 LSB.
- N > 65, a non-unit domain, or maxLattice lowered to 33 after measurement: the cube is resampled onto the lattice and a visible "not 1:1" warning is shown.
- Draft: draftStride(L, refinement) = the smallest s ≥ 2 that divides the refinement k (L−1 = k(N−1)) and leaves
  (L−1)/s+1 ≥ 9 nodes, else 1. latticeSizeFor returns the refinement; callers pass it into the bake job. For 33 that
  is s = 2 (17³ nodes); a refined look gets a stride on its own nodes (13³ → 37: 3, 15³ → 43: 3) or no draft
  (4³ → 34: 1), so a draft of an exact look never pops.
  - The bake fills the skipped nodes with a separable r → g → b multilinear fill, which is exactly what a coarse texture would render.
  - Drafts are used only while dragging, and only if the last final bake took longer than config grade.draftWhenFinalOverMs (8). A desktop at about 5-8 ms therefore never shows a draft-to-final pop.

2.7 Bake cost
- Measured by the design prototypes of this model (node 24, this desktop):
  - 33³ final: 5.0-7.5 ms with every control on;
  - 17³ draft: about 1.3-2.4 ms;
  - 41³: about 10 ms;
  - 65³: about 36-56 ms;
  - pack: 0.25 ms (Float16Array), 1.1 ms (u32 packer).
- A neutral grade costs nothing: the cached identity is copied.
- Phones are estimated 4-6× slower, off the main thread.

3. .cube PARSER AND WRITER (cube-format.ts, pure)

parseCube(text): CubeFile

    { title: string | null, kind: '3d' | '1d' | '1d+3d',
      size: number (3D N, 0 if none), domainMin: [r,g,b], domainMax: [r,g,b], data: Float32Array (RGB, red fastest),
      lut1d: { size, domainMin, domainMax, data: Float32Array } | null, warnings: string[] }

How it reads a file:
- Lines split on /\r\n|\r|\n/.
- TITLE is handled first, so a quoted title may contain '#'; quoted and unquoted titles are both accepted.
- Everything after '#' is a comment. Lines are trimmed; blank lines are skipped anywhere, including after the data.
- Tokens are split on /[ \t]+/.
- Keywords are matched case-insensitively: TITLE, LUT_1D_SIZE, LUT_3D_SIZE, DOMAIN_MIN, DOMAIN_MAX, LUT_1D_INPUT_RANGE, LUT_3D_INPUT_RANGE.
- A scalar INPUT_RANGE becomes the domain on all channels. DOMAIN wins over INPUT_RANGE, with a warning.
- Unknown keywords before the data are ignored with a warning.
- Numbers must match /^[+-]?(\d+\.?\d*|\.\d+)([eE][+-]?\d+)?$/ and be finite. Signs and exponents are allowed; NaN and Infinity are rejected.
- Data rows are exactly 3 numbers. Values outside [0,1] are kept; nothing wraps.
- With both sizes present, the first N1 rows are 1D and the next N3³ rows are 3D.

It throws CubeParseError(message, line) on:
- a keyword after the data;
- a row that is not exactly 3 numbers;
- a non-number;
- a count that is not exactly N³ (+N1 when a 1D table is present), with expected and found counts in the message;
- a 3D size outside 2..256 or a 1D size outside 2..65536;
- no size keyword.

Import acceptance in v1:
- kind '3d' only.
- kind '1d' or '1d+3d' is rejected in the Look status line: "This .cube has a 1D table (LUT_1D_SIZE n). 1D and shaper LUTs are not supported yet; export a 3D LUT (for example 33 point) instead." It is parsed correctly, never misread.

Other functions:
- sampleLattice(data, n, rgb, out): CPU trilinear with clamp to the lattice.
- isIdentityLattice(data, n, eps = 1e-5).
- serializeCube(lattice: Float32Array, n, { title, comments }) writes:
  - LF only;
  - comment lines only at the top:
    - "# SCHNELLE BUNTE BILDER · Canopy colour grade"
    - "# Input: the displayed frame, sRGB-encoded, after the film look. Take the screenshot with the grade off."
    - "# Interpolation: trilinear"
  - TITLE "…" and LUT_3D_SIZE n;
  - no DOMAIN lines (the default [0,1]);
  - 6 decimals, red fastest, values unclamped (finite).
- Export source: the worker's last final float lattice, at the current lattice size. The file is downloaded as canopy-grade-<n>.cube.

5.9 Responsiveness
- 'input' and pointermove:
  - patch the state (no history push);
  - mark the widget dirty; redraws are coalesced to one per rAF, under 1 ms at dpr 3;
  - call scheduler.request({ state, look, n, stride: draft ? draftStride(n) : 1 }), with draft = lastFinalMs > draftWhenFinalOverMs;
  - post about 2 KB to the worker.
  All of this is under 0.1 ms per event.
- Worker results arrive asynchronously. update() applies the newest one before the next render.
- Commits ('change', pointerup, the end of a 400 ms keyboard-nudge debounce, and every discrete click):
  - push history (structuredClone of {state, look}, capped at 100);
  - request a final bake;
  - re-evaluate compile-in.
- Look import: the file text is posted once ({kind:'parse'}). Parsing never runs on the main thread unless there is no Worker.
- Boot look: config grade.look is fetched from `${import.meta.env.BASE_URL}grades/<file>`, then parsed and baked. The first frames show the grade without the look.

- Fuzz: 200 seeded random states within the ranges, each with and without a look, give only finite values within [−16, 16].
- Error budget: a busy grade at 33, CPU trilinear with 8-bit weights emulated, against evaluateGrade on a dark-green ramp (sRGB 20-110) and a sky ramp. Assert max ≤ 2.5 LSB and share > 1 LSB ≤ 8 %; log the figures and tighten after the first run.

- Scheduler with a fake post that simulates transfer with structuredClone(msg, { transfer: [msg.out] }):
  - one job in flight;
  - latest wins;
  - a commit promotes the pending job to final;
  - a duplicate final is skipped;
  - a stale seq is dropped;
  - draft only above the threshold;
  - identityTexels(33).buffer.byteLength and the current array's buffer are never detached;
  - the pool drops buffers of another size.

7. BROWSER MEASUREMENTS

Setup
- Dev server colour-dev (npm --prefix <worktree>/viewer run dev, port 5177, the uncommitted launch.json).
- A background tab, ?bgclock, resize_window 1280×800, rain cycle off, a frozen bench pose.
- Ask before any multi-minute run in the user's pane.
- Pixel-exact captures go through plans/grade-editor/capture_server.py as PNG.
- Results go into the Canopy Colour Matching artifact (https://claude.ai/artifact/JjMNnLFjremEdsYPSSKqUg): read it, then update it by url with a dated changelog entry on top. Never republish it.

GPU method (from the tone-mapping work)
1. Stop the animation loop (renderer.setAnimationLoop(null)).
2. Pin the size by shadowing setSize and setPixelRatio.
3. Before every manual render: r.info.reset(); nodeFrame.update(); r.info.frame = nodeFrame.frameId; then __three.depthOfField.render().
4. Read that render's pass timestamps from the pool after its own resolve. Never group by rAF tick.
5. Pair each state against two identical baselines.

The final quad is its own render, so its timestamp isolates the tap.

M1. Compile-out identity (blocks C3)
- Grade off, and grade neutral with the section closed, against 81ccfab, using the old-vs-new A/B technique (two dev servers, shader hashes, build counters).
- Expected: post-quad and output-quad shader source hashes equal, canvas PNG 0 differing pixels.
- Matrix: WebGPU and ?webgl, path A and path B (?dof=0&edl=0).

M2. GPU cost, via __three.grade.setStage
- States:
  - (a) off ×2;
  - (b) 'passthrough' (routing only);
  - (c) 'grade' with the identity LUT;
  - (d) a busy grade at 33;
  - (e) (d) plus split 0.5;
  - (f) refined lattices 41 and 63, and 65.
- Matrix: paths A and B, WebGPU and ?webgl.
- Accept on desktop:
  - tap (c−a on path A) ≤ 0.05 ms;
  - path B routing (b−a) ≤ 0.02 ms, otherwise build the film-slot fallback (1.7);
  - 41/63/65 against 33 ≤ 0.02 ms.
- Then one phone over npm run dev:https (Android Chrome WebGPU, iOS Safari): total ≤ 0.3 ms, otherwise set maxLattice to 33.
- Use fps A/B with ?grade=0|1 where timestamps are unavailable.

M3. Recompile counter
- 0 during 10 s drags of every slider and widget.
- 1 'Render Pipeline' build on section open with the grade on; 1 on close at identity; 1 per toggle.
  Count by name (wrap renderer.backend.createNodeBuilder): with DoF and EDL on each change is 9
  builds in all, 7 with DoF alone, 1 on path B. Texture count must stay flat across repeated changes.
- 0 on Compare toggle, split drag, same-size uploads and look amount drags.
- A size swap should give 0; if it gives 1, note it (one hitch per import is acceptable).

M4. Identity flip rate: compiled in at identity against compiled out. Percentage of pixels changed and max delta; expect ≤ 1 level and < 3 %. This replaces the 1-3 % estimate.

M5. LUT correctness
- With a busy grade, capture all-before (split 2) and all-after.
- Apply the exported lattice (parseCube of Export .cube) on the CPU with trilinear to the before PNG and compare to after: mean ≤ 0.3 LSB, max ≤ 2 LSB.

M6. .cube round trip
1. In-app: set a grade, export, Reset, import, then diff against the pre-export capture. Expect max 1 level and < 1 % of pixels changed.
2. Fuji F125 Kodak 2393 (21³ → 41):
   - the after capture against the cube's own CPU trilinear on the before capture: ≤ 1 level;
   - nudging temperature to +1 and back returns the same frame;
   - with temperature +1, the max change against the look alone stays at the size of the control (no 15 LSB jump).
3. Resolve (DaVinci YRGB without colour management, full data levels, 3D LUT interpolation Trilinear):
   - grade the Frame-for-grading PNG, Generate a 33 Point Cube, import it, and compare against Resolve's still: mean ≤ 0.5 LSB, max ≤ 2-3 LSB;
   - the reverse: apply our export in Resolve to the same PNG and compare to our after capture.
   - Record Resolve's default interpolation and pivot, which are unverified so far.
4. Photoshop: an sRGB PNG with Curves and Hue/Saturation layers, Export → Color Lookup Tables (CUBE), import, compare with the same thresholds.

M7. Canvas clamp
- A grade storing values > 1 and < 0 (gain 2, offset −0.1, no roll-off).
- The display must equal clamp(CPU trilinear) on both backends, with no NaN or garbage.

M8. Frame for grading

10. RISKS LEFT
1. Phone 3D-tap throughput and the cost of 41-65³ refined lattices are unmeasured. Fallback: maxLattice 33, which resamples with a "not 1:1" warning.
2. Path B routing cost is unmeasured. Fallback: the film-slot variant, which then only covers path B with Film picked and the stage on.
3. While the section is open at identity, an identity LUT runs and may flip about 1-3 % of pixels by one level. That is invisible and limited to editing, but it still has to be measured (M4).
4. Opening the section recompiles the post quad once. The hitch per backend is unmeasured.
5. Display-referred limits:
   - the LUT sees shouldered, clamped film output and cannot recover highlights;
   - film saturation 1.17 already clips negative blue on saturated canopy;
   - exposure stays scene-linear in Tone & colour.
6. The canvas is 8-bit with no dither, so shadow-stretching grades can band in dark greens (M11, later step 4).
7. Interpolation at 33³: a strong combined grade measured about 2.2 LSB max on dark greens, before the C1 fixes. 65³ halves it.
8. Interop:
   - wheel numbers never match Resolve or Lightroom; only .cube round-trips;
   - Resolve must be set to trilinear;
   - Lightroom has no .cube, and Evergreen's spatial tools can never be a LUT;
   - 1D and shaper cubes are rejected in v1;
   - non-unit-domain 3D cubes are resampled.
9. A look configured in config.grade.look loads asynchronously, so the first frames show the grade without it.
10. Copy values cannot carry a lattice. An imported look must be saved under public/grades/ to persist.
11. The Design panel ships unguarded in production. It is collapsed and neutral by default, so the shader is identical.
12. The loader eagle and the splat layer use their own renderers and get neither film nor grade.
13. Hexcone hue has sextant kinks that the 0.05 chroma gate damps. Slight shimmer on low-chroma haze is possible and must be checked visually.
14. Firefox WebGPU is untested. The tap is uniformity-safe by construction (textureSampleLevel plus a uniformFlow select).
15. Older Safari lacks Float16Array; the bit-identical u32 packer covers it.
